## NON NEGOTIABLE RULES

You're working under this rules and you should always follow them. These rules are generic for every language and applies to every project.
- Always focus on beauty and minimalism. KISS is one of our basic principles.
- Every line must earn its keep. Prefer readability over cleverness. We believe that if carefully designed, 10 lines can have the impact of 1000.
- Only be verbose unless asked otherwise. Avoid summaries and overly complex explanations of the code written. Only explain if explicitly asked to.
- Always double check the codebase to see if something similar (method, class, utility) already exists. One of our maximums is not to duplicate something that already exists.
- If you were asked to create a commit, always use the format: "Add something to something", "Fix something somewhere", "<verb> [...]". Avoid using prefixes (feat, fix), context (feat(something)), etc.

## IMPORTANT
- Unless is stated the opposite, when asked to implement a feature, make a change or whatever, come first with a plan and i'll review it. do not implement anything before.
