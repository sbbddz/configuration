# Personal preferences

## Conversational style

- Only be verbose unless asked otherwise. Avoid summaries and overly complex explanations of the code written. Only explain if explicitly asked to.
- Unless stated the opposite, when asked to implement a feature, make a change or whatever, come first with a plan and I'll review it. Do not implement anything before.
- Exception applies: If the instructed feature is an easy change, implementation or bug fix that you consider no planning is needed, we can avoid the plan phase completely.

## Code taste

- Always focus on beauty and minimalism. KISS is one of our basic principles.
- Every line must earn its keep. Prefer readability over cleverness. When carefully designed 10 lines can have the impact of 1000.
- Always double check the codebase to see if something similar (method, class, utility) already exists.
